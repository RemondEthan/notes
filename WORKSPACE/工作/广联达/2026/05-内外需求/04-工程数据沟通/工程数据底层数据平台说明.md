## 1. 平台定位

工程数据底层数据平台是广材网、指标网及后续 B/G 能力输出的 **统一数据底座**。平台承接多源、异构工程造价与材料相关数据，完成 **采集 → 清洗 → 标准化 → 搜索 → 业务应用** 全链路处理，为上层 SaaS 产品、分析报表及 AI/CLI 工具层提供可信、可检索、可计算的数据能力。

**平台核心价值：**

| 维度 | 说明 |
|------|------|
| **统一接入** | 支持 Excel、GBQ、XML、JSON 等多格式工程数据文件批量入库 |
| **结构化沉淀** | 将非结构化/半结构化文件解析为项目、清单、材料、用量等标准实体 |
| **标准一致** | 通过材料字典、清单字典、指标字典消除口径差异，支撑跨项目、跨来源比对与指标计算 |
| **高效检索** | 提供面向清单与材料的条件搜索与关联查询 |
| **规则驱动业务** | 支撑同材料/同清单载价、清单调差、指标计算等造价业务场景 |
| **规模可扩展** | 基于 TB 级数据湖仓，满足历史样本持续积累与高性能分析需求 |

## 2. 总体架构

平台按 **接入层 → 处理层 → 标准层 → 服务层 → 应用层** 分层建设，各层职责清晰、可独立演进：

| 层次 | 组件 |
|------|------|
| **业务应用层** | 清单载价 · 材料载价 · 指标计算 · 价格审核 |
| **搜索服务层** | 清单检索 · 材料检索 · 条件筛选 · 关联推荐 |
| **标准层** | 材料字典 · 清单字典 · 指标字典 · 关系图谱 |
| **处理层** | 清洗 · 解析 · 要素识别 · 属性提取 · 质量校验 |
| **接入层** | Excel · GBQ · XML · JSON · 批量任务 · 增量同步 |
| **数据湖仓** | 原始区（ODS）· 明细区（DWD）· 主题区（DWS）· 应用区（ADS） |

**核心数据实体关系：**

```
项目（Project）
  └── 清单（Bill / BOQ Item）
        └── 材料用量（Material Usage）
              └── 材料（Material）
```

一条完整造价样本自顶向下包含：**项目基本信息 → 分部分项清单 → 清单下挂材料及用量 → 材料属性与价格信息**。平台以该实体模型贯穿采集、清洗、标准化与业务计算全流程。

## 3. 业务事理

平台处理的工程数据，在业务上可区分为 **材料价格数据** 与 **清单价格数据** 两大类。二者来源不同、时效特征不同，在载价与指标计算中的应用方式亦不同。理解这一区分，是正确使用平台能力的前提。

### 3.1 材料价格数据

材料价格是 **单种材料在某一时点的单价**，是组价、载价与调差计算的基础单元。平台汇聚三类来源：

| 来源类型 | 说明 | 特点 |
|----------|------|------|
| **政府信息价** | 各地造价主管部门定期发布的材料参考价格 | 权威、周期固定（通常按月/季），覆盖主流材料，是调差计算的基准 |
| **人工采集的市场价** | 运营人员通过询价、调研等途径采集的实际成交或报价 | 贴近市场、更新灵活，品类与规格覆盖更广 |
| **测定价** | 基于用户行为数据（查询、选用、成交等）计算得出的参考价格 | 反映用户真实偏好与市场热度，随行为数据持续迭代 |

**业务要点：**

- 材料价格具有显著的 **时效性**——同一材料在不同时点价格不同，入库时必须记录 **价格时点**（及地区、来源等上下文）。
- 三类来源在载价时可按业务规则设定 **优先级**（如信息价优先用于调差、市场价优先用于组价等）。
- 广材网的核心数据资产即围绕材料价格展开，平台需支撑多来源价格的并存、更新与检索。

### 3.2 清单价格数据

清单价格是 **某个清单项在特定项目、特定时点的综合单价**（含人工、材料、机械等费用构成），反映的是「整项工程内容」的造价水平，而非单一材料价格。

**主要来源：**

| 来源类型 | 说明 | 典型文件 |
|----------|------|----------|
| **实际施工项目的计价文件** | 人工采集的已完或在建项目造价成果 | GBQ 计价文件、XML 交换文件等 |
| **政府中标文件** | 公共资源交易平台发布的中标价清单 | 中标清单 Excel、XML、PDF 解析结果等 |

**业务要点：**

- 清单价格来自 **真实项目样本**，是指标网进行造价对标、指标计算的核心输入。
- 清单价格隐含了编制时点的材料价格水平；其综合单价 ≠ 当前时点的材料价格简单加总。
- 入库时需保留 **清单编制时间**、项目地点、工程类型等元数据，以便后续调差与对标。

### 3.3 时效性与清单调差

材料价格的时效性，决定了 **历史清单价格不能直接用于当前时点的造价判断**，应用在载价或对标场景时必须做 **价格调差**。

**调差逻辑（一般做法）：**

```
历史清单综合单价
  → 拆解或关联清单下的材料构成及用量
  → 识别受材料价格波动影响的部分
  → 以政府信息价为基准，计算「清单编制时点 → 当前应用时点」的材料价格变动率（波动率）
  → 按波动率对材料费（或相应构成）进行调整
  → 得到适用于当前时点的调整后清单价格
```

**示意：**

| 环节 | 说明 |
|------|------|
| **基准选择** | 通常参考 **政府信息价**，因其时序连续、地区可比 |
| **波动率计算** | 对清单中主要材料，取编制期信息价与应用期信息价之比（或指数差），形成调差系数 |
| **适用范围** | 主要作用于材料价随时间变化明显的清单；人工、机械等可按规则单独处理或锁定 |
| **平台支撑** | 平台需维护信息价时序数据、清单—材料挂接关系及编制时点，供调差引擎自动计算 |

**与载价的关系：**

- **同材料载价**：直接匹配当前或指定时点的材料价格，侧重「材料维度」。
- **同清单载价**：匹配历史清单样本后，往往需 **先调差再套用**，使历史综合单价对齐当前材料价格水平。
- **指标计算**：样本入库时间与应用时间不一致时，亦需按口径决定是否调差后再汇总指标。

## 4. 数据采集

### 4.1 采集目标

从多渠道、多格式来源持续采集工程数据文件，形成平台原始数据资产，为后续清洗与标准化提供输入。

### 4.2 支持的数据格式

| 格式 | 典型来源 | 说明 |
|------|----------|------|
| **Excel** | 政府信息价表、市场价汇总表、中标清单 | 信息价与清单样本的常见载体；行列结构不统一，需模板识别 |
| **GBQ** | 实际施工项目计价文件 | 含完整项目、清单、定额、材料、价格等结构化信息 |
| **XML** | 造价数据交换标准、政府中标文件导出 | 遵循地方或行业 schema，需适配解析器 |
| **JSON** | 测定价计算结果、内部接口、用户行为聚合 | 字段灵活，适合增量同步与实时接入 |

**按业务类型的采集侧重：**

| 数据类型 | 主要来源 | 主要格式 |
|----------|----------|----------|
| **材料价格** | 政府信息价、人工市场价、测定价 | Excel、JSON |
| **清单价格** | 实际项目计价文件、政府中标文件 | GBQ、XML、Excel |

### 4.3 采集方式

- **批量导入**：支持按项目、按批次上传文件，触发解析流水线。
- **定时同步**：对接内部业务系统或外部数据源，按调度策略增量拉取。
- **接口接入**：通过 REST / 消息队列接收 JSON 等结构化 payload。
- **元数据登记**：采集时记录来源类型（信息价/市场价/测定价/项目样本/中标文件）、价格或编制时点、地区、版本、上传时间、文件哈希等，支撑溯源、调差与重跑。

### 4.4 采集层输出

采集完成后，原始文件及基础元数据写入数据湖仓 **原始区（ODS）**，保留「原貌存档 + 可重放解析」能力，不因下游规则变更而丢失源头信息。

## 5. 数据清洗与结构化提取

### 5.1 清洗目标

将 ODS 中的异构文件转化为平台统一的结构化明细，提取并关联四类核心信息：

| 信息类型 | 主要内容 | 示例字段 |
|----------|----------|----------|
| **项目信息** | 工程概况与造价上下文 | 项目名称、工程类别、建设地点、造价阶段、编制时间 |
| **清单信息** | 分部分项及清单项 | 清单编码、名称、单位、工程量、综合单价、合价、**编制时点** |
| **材料信息** | 材料本身属性 | 材料编码、名称、规格型号、单位、单价、**价格来源**（信息价/市场价/测定价）、**价格时点**、品牌 |
| **清单下材料用量信息** | 清单与材料的挂接关系 | 所属清单、材料 ID、消耗量、损耗率、合价 |

### 5.2 清洗处理流程

```
原始文件
  → 格式识别与解析（按 Excel / GBQ / XML / JSON 分流）
  → 字段映射与类型转换
  → 去重、空值处理、异常值检测
  → 实体抽取（项目 / 清单 / 材料 / 用量）
  → 关联关系建立（清单—材料—项目）
  → 质量规则校验
  → 写入明细区（DWD）
```

### 5.3 主要清洗能力

- **格式统一**：不同来源的同类字段映射到统一 schema（如「规格」「规格型号」「型号规格」归一）。
- **去重与合并**：同一项目多次入库时，按业务规则识别重复或版本关系。
- **异常处理**：缺失必填项、工程量/单价逻辑矛盾、编码格式错误等标记为待审核或自动修正。
- **人工审核衔接**：对高价值样本或低置信度解析结果，支持人工复核后回流标准层。

## 6. 数据标准化与字典体系

### 6.1 标准化目标

解决「同名不同义、同义不同名、规格表述混乱、指标口径不一」等问题，使跨项目、跨来源的清单、材料与造价指标具备 **可比对、可关联、可计算** 的统一语义。

### 6.2 材料字典

材料字典是平台对材料实体的 **标准定义与编码体系**，核心能力包括：

- **标准材料编码**：为每种标准材料分配唯一标识。
- **要素识别**：从材料名称、规格型号等文本中识别品类、规格、材质、品牌等要素。
- **属性提取**：结构化提取关键属性（如管径、壁厚、强度等级、计量单位等）。
- **映射关系**：建立原始材料 → 标准材料的映射，保留多对一归并能力。
- **版本管理**：字典随行业标准、企业口径变更而迭代，支持历史数据回溯。

### 6.3 清单字典

清单字典是平台对清单项（分部分项）的 **标准定义与编码体系**，核心能力包括：

- **标准清单编码**：统一清单项标识，兼容国标、地方清单及企业清单口径。
- **要素识别**：识别清单名称中的工程内容、做法、计量特征等要素。
- **属性提取**：提取单位、工作内容、特征描述等结构化属性。
- **层级结构**：支持分部—分项—清单项的层级组织与检索。

### 6.4 指标字典

指标字典是平台对工程造价 **指标项** 的标准定义与口径体系，为指标网及指标计算引擎提供统一语义，核心能力包括：

- **标准指标编码**：为单方造价、分部分项指标、主要材料含量指标等分配唯一标识。
- **口径定义**：明确各指标的计算范围、计量单位、汇总层级与包含/排除规则。
- **计算规则**：定义指标由哪些清单、材料数据聚合而来，以及调差、加权等处理逻辑。
- **维度体系**：支持按工程类型、专业、地区、造价阶段等维度组织与检索指标。
- **版本管理**：指标口径随业务规范变更而迭代，支持历史指标回溯与对标。

### 6.5 标准化输出

标准化结果写入 **主题区（DWS）**，形成：

- 标准材料宽表 / 标准清单宽表 / 标准指标定义表
- 材料关系图谱、清单关系图谱（见 §9.2）
- 指标口径与计算规则配置

## 7. 搜索与检索服务

### 7.1 服务目标

为上层产品与业务引擎提供 **高效、灵活** 的清单与材料检索能力，使用户与系统能按条件快速定位入库数据。

### 7.2 检索对象

| 检索对象 | 典型检索维度 |
|----------|--------------|
| **材料** | 名称、规格、编码、地区、价格区间、来源、标准材料 ID |
| **清单** | 名称、编码、单位、工程类别、地区、项目类型、标准清单 ID |
| **项目** | 项目名称、地点、造价阶段、编制时间、工程规模 |

### 7.3 检索能力

- **条件组合搜索**：支持多字段 AND/OR 组合、范围筛选、模糊匹配。
- **全文检索**：对名称、特征描述、备注等文本字段建立索引。
- **标准 ID 检索**：按标准材料/清单 ID 反查所有关联原始样本。
- **关联扩展**：检索某材料时，可关联展示使用该材料的清单及所属项目。
- **排序与聚合**：按相关度、时间、价格时点、使用量等排序；支持分组统计。

### 7.4 服务形态

- 对内：为广材网、指标网及载价/指标引擎提供统一查询接口。
- 对外（远期）：可封装为 API / CLI，供 Agent 或第三方系统调用。

## 8. 业务应用层

业务应用层基于标准化后的清单与材料数据，按 **可配置业务规则** 执行造价领域核心场景。应用逻辑须结合 §3 所述业务事理——尤其是材料价格的时效性与清单调差要求。

### 8.1 载价（价格套用）

**载价** 指根据业务规则，将已有价格数据套用到目标清单或材料上，减少重复询价与组价工作。

| 载价类型 | 规则逻辑 | 典型场景 |
|----------|----------|----------|
| **同材料载价** | 按标准材料 ID 或材料等价关系，匹配指定时点的信息价、市场价或测定价 | 组价时自动填充材料单价 |
| **同清单载价** | 按标准清单 ID 或清单等价/包含关系，匹配历史项目样本的综合单价 | 新建项目快速组价、对标报价 |
| **清单调差后载价** | 匹配历史清单样本后，按 §3.3 以信息价波动率调差至当前时点，再套用 | 跨期对标、历史样本用于当前估价 |

**规则引擎要点：**

- 支持按地区、**价格时点**、项目类型、价格来源优先级（信息价 / 市场价 / 测定价）筛选候选价格。
- 同清单载价默认触发 **调差流程**：基于清单编制时点与应用时点的信息价变动率，调整材料费构成。
- 支持「完全匹配优先、近似匹配备选」的多级策略。
- 载价结果可记录规则版本、调差系数与命中路径，便于审计与复核。

### 8.2 指标计算

基于入库的清单与材料明细数据，按指标口径规则 **聚合计算** 工程造价指标，支撑指标网及分析类应用。

**典型指标类型：**

| 指标类别 | 示例 |
|----------|------|
| **项目级** | 单方造价、总造价、单位造价指标 |
| **专业/分部** | 土建、安装、装饰等各专业造价占比 |
| **清单级** | 分部分项指标、主要清单项指标 |
| **材料级** | 主要材料含量指标、材料费占比 |

**计算逻辑：**

- 输入：标准化清单、材料用量及价格数据 + 指标口径配置。
- 过程：按规则汇总工程量、合价，归集到指标维度；跨期样本按口径决定是否先调差。
- 输出：结构化指标结果，写入应用区（ADS），供检索、报表与对标使用。

### 8.3 与双产品的关系

| 产品 | 平台能力支撑 |
|------|--------------|
| **广材网** | 三类材料价格（信息价/市场价/测定价）的标准化、搜索、同材料载价与时点更新 |
| **指标网** | 项目/中标清单样本入库、清单搜索、调差后载价、指标计算与对标 |

## 9. 关键技术

### 9.1 材料与清单的标准化

标准化是平台的技术核心，解决工程领域文本表述高度非标准化的问题。

**（1）要素识别**

从材料名称、清单名称、特征描述等非结构化文本中，识别出具有业务语义的关键要素：

- 材料：品类（如「镀锌钢管」）、规格（如「DN100×4.0」）、材质、品牌等。
- 清单：工程内容、做法、部位、计量特征等。

技术路径包括：规则模板、词典匹配、序列标注模型（NER）及大模型辅助抽取等，按场景组合使用。

**（2）属性提取**

在要素识别基础上，将文本转化为 **结构化属性字段**，写入标准字典：

```
输入：「热镀锌钢管 DN100×4.0mm 国标」
输出：{ 品类: 钢管, 处理方式: 热镀锌, 管径: 100, 壁厚: 4.0, 标准: 国标 }
```

属性提取质量直接影响载价命中率与指标准确性，是平台持续投入的关键能力。

### 9.2 材料与清单的关系计算

跨来源比对与载价依赖对实体间关系的准确判定，平台需支持以下关系类型：

**材料关系：**

| 关系 | 含义 | 应用 |
|------|------|------|
| **相等** | 两条材料在业务语义上指同一对象 | 同材料载价、价格归并 |
| **包含** | 一条材料在语义上包含另一条（如泛称包含具体规格） | 模糊匹配、推荐候选 |
| **上下位** | 上位材料在品类或规格族上概括下位材料（包含关系的层级化表达） | 层级检索、向上聚合参考价 |

**清单关系：**

| 关系 | 含义 | 应用 |
|------|------|------|
| **相等** | 两条清单项工程内容一致 | 同清单载价、指标对标 |
| **包含** | 一条清单的工作范围包含另一条 | 层级汇总、近似匹配 |
| **上下位** | 上位清单在语义或工程范围上概括下位清单（包含关系的层级化表达） | 粒度对齐、跨项目对标、上位指标汇总 |

详见 [§10.3 上位材料](#103-上位材料)、[§10.4 上位清单](#104-上位清单) 及 [§10.7 需求关联与建设优先级](#107-需求关联与建设优先级)。

**关系计算技术：**

- 基于标准 ID 的精确关联（字典映射后）。
- 基于属性向量的相似度计算（规格、单位、特征多维比对）。
- 基于规则的关系推导（如编码前缀、层级从属）。
- 关系结果持久化为 **关系图谱**，供搜索、载价与指标引擎复用。

### 9.3 其他支撑技术

| 技术领域 | 作用 |
|----------|------|
| **解析引擎** | 多格式文件（GBQ / XML / Excel / JSON）的结构化解析 |
| **规则引擎** | 载价规则、调差规则、指标口径、清洗规则的 configurable 执行 |
| **调差引擎** | 基于信息价时序数据，计算编制期至应用期的材料价格波动率并调整清单价格 |
| **任务调度** | 批量采集、清洗、标准化流水线编排与监控 |
| **质量监控** | 解析成功率、标准化覆盖率、载价命中率等指标看板 |

## 10. 技术需求与痛点

本节从 **材料标准化、清单标准化、上位关系、TB 级存储、数据检索** 五个维度，归纳平台当前及下一阶段必须解决的技术需求与主要痛点，供研发优先级与能力建设参考。

### 10.1 材料标准化

**技术需求：**

| 需求项 | 说明 |
|--------|------|
| **统一标准编码** | 为每种标准材料分配全局唯一 ID，支撑跨项目、跨来源的价格归并与载价 |
| **要素识别与属性结构化** | 从「名称 + 规格型号」等非标准文本中识别品类、规格、材质、品牌等要素，并写入结构化字段 |
| **多源映射归一** | 建立「原始材料 → 标准材料」映射，支持多对一归并，保留映射置信度与来源追溯 |
| **口径与版本管理** | 字典随行业标准、企业规范迭代，历史映射可回溯，不因字典升级导致历史载价失效 |
| **持续覆盖扩展** | 对新入库材料自动触发标准化流水线，并逐步扩大字典覆盖率 |

**主要痛点：**

- **表述高度非标准化**：同一材料存在「DN100×4.0」「φ100×4」「100 钢管 4mm 壁厚」等多种写法，规则难以穷举。
- **同义异名、异义同名**：「镀锌钢管」与「热镀锌焊接钢管」可能指同一对象；「普通混凝土」在不同语境下强度等级不同。
- **规格维度组合爆炸**：品类 × 规格 × 材质 × 品牌组合数量巨大，纯人工维护字典不可持续。
- **映射覆盖率与准确率矛盾**：高召回易引入误映射，高精度则大量样本无法自动归一，依赖人工审核，成为入库瓶颈。
- **新物料涌现快**：新材料、新品牌、新规格持续出现，字典滞后直接影响载价命中率与价格审核能力。

### 10.2 清单标准化

**技术需求：**

| 需求项 | 说明 |
|--------|------|
| **统一标准清单编码** | 兼容国标清单、地方清单及企业清单口径，形成平台级标准清单 ID |
| **工程内容要素识别** | 从清单名称、项目特征描述中识别做法、部位、计量特征等语义要素 |
| **单位与计量归一** | 统一计量单位及换算规则，支撑工程量与单价的跨样本比对 |
| **特征描述结构化** | 将长文本特征拆解为可检索、可比对的标准属性字段 |
| **层级结构维护** | 支持分部—分项—清单项的组织方式，并与标准清单树对齐 |

**主要痛点：**

- **地方清单体系差异大**：各省清单编码规则、分部划分、特征描述习惯不同，难以用单一 schema 覆盖。
- **特征描述非结构化**：项目特征多为自然语言长文本，关键信息（做法、厚度、遍数等）嵌入其中，解析难度大。
- **清单项粒度不一致**：不同项目对同一工程内容的拆分粗细不同（合并项 vs 细分项），直接比对易产生偏差。
- **新旧清单版本并存**：清单定额改版后，历史样本与新项目口径不一致，需版本映射与对标规则。
- **标准化依赖材料挂接质量**：清单调差、指标计算均依赖清单—材料关系；清单未标准化则下游载价与指标均不可靠。

### 10.3 上位材料

**上位材料** 指在材料语义层级中 **处于更抽象、更泛化层级** 的标准材料节点；下位材料在其工程含义上更具体、更专指。上下位关系是材料「包含」关系的结构化表达，是同材料载价、模糊匹配与推荐的核心依据。

**技术需求：**

| 需求项 | 说明 |
|--------|------|
| **材料层级树构建** | 建立「品类 → 系列/规格族 → 具体规格 → 品牌/型号」等多级树形结构 |
| **上下位关系定义** | 明确上位材料对下位材料的语义覆盖范围，支持一对多、多层级从属 |
| **关系自动推导与人工校核** | 结合编码规则、属性包含逻辑与相似度计算生成候选关系，低置信度人工确认 |
| **载价与检索复用** | 检索上位材料时可扩展至全部下位样本；下位无精确价格时可向上位聚合参考价 |
| **关系图谱持久化** | 上下位关系写入材料关系图谱，供搜索、载价、指标引擎统一调用 |

**主要痛点：**

- **层级边界模糊**：「钢管」「镀锌钢管」「热镀锌无缝钢管 DN100」的上下位划分缺乏行业统一标准，易产生交叉与重复。
- **泛称与专名混用**：原始数据中大量出现「管材」「钢筋」等泛称，难以自动判定应挂载至哪一上位节点。
- **关系维护工作量大**：材料品类持续扩展，上下位关系需随字典迭代更新，纯人工维护成本高、一致性难保障。
- **包含匹配误判风险**：上位过宽导致载价命中错误规格；上位过窄则无法形成有效候选集，影响召回率。
- **与价格时点耦合**：同一材料族下不同规格、品牌价格差异显著，上位聚合价需明确统计口径（中位数、加权等）。

### 10.4 上位清单

**上位清单** 指在清单语义层级或工程内容范围上 **更概括、工作范围更广** 的标准清单项；下位清单在其工程内容、做法或计量范围上更具体，或被上位清单所包含。该关系支撑同清单载价、层级指标汇总与近似对标。

**技术需求：**

| 需求项 | 说明 |
|--------|------|
| **清单层级树构建** | 对齐分部—分项—清单项结构，并扩展标准清单间的上下位语义树 |
| **包含关系判定** | 识别「上位清单工作范围覆盖下位清单」的语义包含，区分相等、包含、交叉等关系 |
| **粒度对齐能力** | 支持粗粒度清单项与细粒度拆分项之间的映射，服务跨项目对标 |
| **与材料构成联动** | 上位清单的调差与载价需能向下拆解或关联到下位清单及材料构成 |
| **关系版本管理** | 清单体系改版时，上下位关系同步迁移，保障历史样本仍可对标 |

**主要痛点：**

- **拆分粒度差异显著**：同一「外墙涂料」在不同项目中可能拆为一道清单或多道（基层、面漆、保温等），上位归并规则复杂。
- **包含关系语义判定难**：需理解工程做法与工作内容，纯规则难以覆盖，依赖 NLP / 大模型辅助但仍需人工抽检。
- **交叉与重叠**：部分清单项工作范围部分重叠而非严格包含，关系类型需细分为包含、交叉、互斥等，增加建模复杂度。
- **指标汇总口径冲突**：上位清单聚合指标时，若下位样本重复计量或遗漏，将导致指标失真。
- **地方清单与国标清单树不一致**：建立跨口径的上位清单映射层是长期工程，短期覆盖率有限。

### 10.5 TB 级数据存储

**技术需求：**

| 需求项 | 说明 |
|--------|------|
| **海量样本持续入湖** | 支撑历史项目、中标文件、信息价等多源数据长期积累，数据规模达 TB 级 |
| **原始数据只追加、可重放** | ODS 保留原始文件与 payload，字典或解析规则变更后可重跑，不丢源头 |
| **分层存储与冷热分离** | ODS / DWD / DWS / ADS 职责清晰，冷数据归档、热数据近线，控制成本 |
| **弹性水平扩展** | 存储与计算资源随数据量增长线性扩展，避免单机瓶颈 |
| **批流一体接入** | 批量历史导入与增量实时同步统一入湖，保障数据时效 |
| **治理与血缘** | 分区管理、生命周期策略、血缘追踪，支撑审计与问题溯源 |

**主要痛点：**

- **存储成本持续攀升**：原始 GBQ / XML / Excel 文件量大且需长期留存，TB 级存储与备份成本显著。
- **写入与查询性能矛盾**：明细层细粒度写入量大；高频检索、指标批算、即席分析对 IO 与计算资源争抢。
- **重跑与版本回溯开销大**：标准化规则或字典升级后，全量 DWD / DWS 重算耗时长，影响数据上线周期。
- **小文件与元数据膨胀**：海量项目文件导致 ODS 小文件过多，影响列表、扫描与调度效率，需合并与分区策略优化。
- **跨层一致性保障难**：ODS → DWD → DWS 流水线任一环节失败或延迟，上层应用面临数据不完整或口径不一致风险。

### 10.6 数据检索

**技术需求：**

| 需求项 | 说明 |
|--------|------|
| **多维组合检索** | 支持材料 / 清单 / 项目多字段 AND / OR、范围筛选、模糊匹配 |
| **全文 + 结构化联合检索** | 对名称、特征描述等文本建全文索引，同时支持标准 ID、编码等精确过滤 |
| **低延迟响应** | 面向 SaaS 在线查询，核心检索场景达到秒级甚至亚秒级响应（P95 SLA） |
| **标准 ID 反查与关联扩展** | 按标准材料 / 清单 ID 反查全部原始样本；检索材料时关联清单与项目 |
| **相关度与业务排序** | 综合文本相关度、价格时点、地区、使用量、样本质量等排序与聚合 |
| **TB 规模下索引可维护** | 增量索引更新、索引与湖仓明细层一致，支撑亿级文档量级 |

**主要痛点：**

- **非标准文本检索效果差**：用户输入「100 镀锌管」与库内「热镀锌钢管 DN100×4.0」表述差异大，纯关键词匹配召回不足。
- **语义检索与结构化条件融合难**：自然语言查询需映射为标准属性 + 全文检索的组合，NL2Query 准确率直接影响体验。
- **TB 数据下索引体积与更新成本**：全量重建索引耗时长；增量更新需保障与 DWS 标准化结果同步，否则检索到过期映射。
- **多维筛选组合爆炸**：地区 × 时点 × 来源 × 工程类型等组合条件导致查询计划复杂，易出现慢查询。
- **载价场景对检索要求更高**：不仅「找到」，还需「找对」——排序需体现标准匹配度、价格时效性、样本代表性，相关度模型建设难度大。
- **检索与湖仓双写一致性**：搜索索引层与湖仓明细层分离部署时，数据延迟或失败会导致「能搜到但详情缺失」或反之。

### 10.7 需求关联与建设优先级

上述需求相互耦合，典型依赖关系如下：

```
材料标准化 ──→ 上位材料关系 ──→ 同材料载价 / 材料检索
清单标准化 ──→ 上位清单关系 ──→ 同清单载价 / 指标汇总 / 清单检索
        │                              │
        └──────────→ TB 级湖仓存储 ←───┘
                              │
                        数据检索服务
```

| 优先级 | 方向 | 理由 |
|--------|------|------|
| **P0** | 材料 / 清单标准化与映射 | 载价、指标、检索的数据质量根基 |
| **P0** | 数据检索（结构化 + 全文） | 直接支撑双产品核心查询体验 |
| **P1** | 上位材料 / 上位清单关系图谱 | 提升模糊匹配、载价召回与指标汇总能力 |
| **P1** | TB 级湖仓分层与索引联动 | 支撑规模增长下的 SLA 与成本可控 |
| **P2** | 语义检索 / NL2Query / 大模型辅助标准化 | 在 P0 / P1 基础上进一步提效 |

## 11. 数据湖仓与规模能力

### 11.1 建设目标

工程数据具有 **来源广、格式杂、积累周期长、样本量大** 的特点。平台采用 **TB 级数据湖仓** 架构，兼顾低成本存储、灵活加工与高性能查询。

### 11.2 分层设计

| 分层 | 名称 | 存储内容 | 特点 |
|------|------|----------|------|
| **ODS** | 原始区 | 原始文件、接口 payload、采集元数据 | 只追加、可重放 |
| **DWD** | 明细区 | 清洗后的项目/清单/材料/用量明细 | 结构化、细粒度 |
| **DWS** | 主题区 | 材料/清单/指标字典、关系图谱、**信息价时序**、汇总宽表 | 面向分析主题 |
| **ADS** | 应用区 | 载价结果、**调差后价格**、指标结果、产品查询宽表 | 面向业务应用 |

### 11.3 湖仓一体能力

- **弹性扩展**：存储与计算资源随数据量增长水平扩展，支撑 TB 级历史样本。
- **批流一体**：批量历史导入与增量实时接入统一入湖。
- **多引擎分析**：支持 SQL 分析、搜索索引、机器学习特征抽取等多样 workload。
- **数据治理**：血缘追踪、分区管理、生命周期策略（冷热分层），控制存储成本。

### 11.4 性能与可靠性

- 高频检索场景（材料/清单搜索）通过索引层加速，与湖仓明细层联动。
- 关键流水线支持失败重试、断点续跑与版本回溯。
- 核心字典（材料/清单/指标）变更可审计，保障指标与载价结果可追溯。

## 12. 能力输出与演进方向

### 12.1 对内价值

- 为广材网、指标网提供统一、高质量的数据底座，降低重复建设。
- 载价与指标计算能力产品化，缩短新业务场景上线周期。
- 数据质量与标准化能力构成核心竞争壁垒。

### 12.2 对外潜力（远期）

平台能力可模块化输出，支撑 B/G 及 AI 工具层战略：

| 输出形态 | 内容 |
|----------|------|
| **数据治理模块** | 采集、清洗、标准化流水线及字典体系 |
| **API / 搜索服务** | 清单与材料条件检索 |
| **载价 / 调差 / 指标引擎** | 规则配置 + 计算服务（含清单调差能力） |
| **CLI / MCP** | 供 Agent 调用的工程数据工具接口 |

### 12.3 演进重点

1. **标准化精度**：持续提升要素识别与属性提取准确率，扩大字典覆盖率。
2. **关系图谱**：丰富材料/清单相等与包含关系，提升载价与对标命中率。
3. **调差能力**：完善信息价时序覆盖与调差规则配置，支撑跨期清单价格应用。
4. **规模与性能**：湖仓架构下 TB 级样本的入库、检索、计算 SLA 优化。
5. **AI 融合**：引入大模型辅助解析与标准化，并与 CLI/Agent 工具层深度整合。

## 附录：术语说明

| 术语 | 说明 |
|------|------|
| **信息价** | 政府造价主管部门发布的材料参考价格，周期性更新，是调差计算的主要基准 |
| **市场价** | 人工采集的市场询价或成交价格，反映实际市场水平 |
| **测定价** | 基于用户行为数据计算得出的材料参考价格 |
| **调差** | 将历史清单价格按材料价格变动（通常参考信息价波动率）调整至当前时点的过程 |
| **GBQ** | 广联达计价工程文件格式，含项目、清单、定额、材料等完整造价信息 |
| **清单** | 分部分项工程量清单项（Bill / BOQ Item），工程造价计量的基本单元 |
| **载价** | 按规则将已有价格套用到目标材料或清单的过程 |
| **材料字典** | 平台对材料的标准定义、编码及属性体系 |
| **清单字典** | 平台对清单项的标准定义、编码及属性体系 |
| **指标字典** | 平台对工程造价指标的标准定义、口径及计算规则体系 |
| **ODS / DWD / DWS / ADS** | 数据湖仓分层：原始区 / 明细区 / 主题区 / 应用区 |
| **要素识别** | 从文本中识别具有业务语义的关键成分（如规格、材质） |
| **属性提取** | 将识别出的要素转化为结构化字段 |
| **相等 / 包含** | 实体间两种核心关系：语义相同；或一方语义覆盖另一方 |
| **上位材料** | 材料层级树中处于更抽象、更泛化层级的标准材料；其工程语义覆盖下位材料 |
| **上位清单** | 清单层级或工程内容范围更概括的标准清单项；其工作范围包含或覆盖下位清单 |
